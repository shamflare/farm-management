# نظام إدارة المزرعة — Farm Management Platform

نظام إدارة مزرعة مبني على محرك محاسبي بالقيد المزدوج: كل حركة مال لها قيد متوازن،
وكل رصيد في النظام محسوب من القيود المرحّلة — لا أرقام إجمالية محفوظة يدويًا.

المزرعة تُدار كفرعين مستقلين — **تربية** و**تسمين** — لكل واحد مستودع أعلافه
ومصاريفه ودخله، فيُقرأ ربح كل فرع لحاله لا كصندوق واحد مختلط.

المواصفات الكاملة في [plan.md](plan.md)، والمعمارية في [docs/architecture.md](docs/architecture.md).

## التشغيل

### 1. الخلفية (Django + DRF)

```bash
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt      # على لينكس: .venv/bin/pip

cd backend
../.venv/Scripts/python manage.py migrate
../.venv/Scripts/python manage.py seed_demo --reset
../.venv/Scripts/python manage.py runserver 8000
```

- الـ API: <http://127.0.0.1:8000/api/v1/>
- توثيق تفاعلي: <http://127.0.0.1:8000/api/docs/>
- مستخدمو التجربة: `owner` / `worker` / `accountant` / `partner` — كلمة المرور `farm1234`
- حسابات إضافية تُنشأ من الواجهة: الإعدادات ← المستخدمون والدخول

### 2. لوحة الإدارة (Next.js)

```bash
cd admin-web
npm install
npm run dev
```

افتح <http://localhost:3000> وسجّل الدخول بـ `owner` / `farm1234`.

### 3. PostgreSQL

القاعدة الهدف هي PostgreSQL. شغّلها عبر:

```bash
docker compose up -d db
cp .env.example .env      # يحتوي DATABASE_URL جاهزًا
```

بدون `DATABASE_URL` يقلع النظام على SQLite محليًا للتجربة السريعة فقط. كل النماذج
متوافقة مع القاعدتين (مفاتيح UUID، أموال NUMERIC، حقول JSON).

## النشر على Render

المستودع يحوي [render.yaml](render.yaml) يصف النشر كاملًا: خدمة للـ API، خدمة
للوحة الإدارة، وقاعدة PostgreSQL — كلها على الخطط المجانية.

من لوحة Render: **New → Blueprint** ثم اختر هذا المستودع، وضع قيمة
`DEMO_PASSWORD` قبل أول نشر.

لتحديث بيانات العرض بعد ميزة جديدة لا تعرفها البيانات القديمة: أضف المتغيّر
`DEMO_RESEED=1` في لوحة Render، انشر، **ثم احذف المتغيّر فورًا** — فهو يمسح
مزرعة العرض ويعيد بذرها في كل نشر ما دام موجودًا.

الترحيل والبذر يجريان في خطوة البناء لا عند الإقلاع، فالخدمة النائمة تعود في
ثوانٍ. والبذر يفحص وجود مزرعة أولًا: `seed_demo` يرحّل قيودًا حقيقية، وتكراره
كان ليضاعف التاريخ المالي.

حدود الخطة المجانية: الخدمات تنام بعد ١٥ دقيقة خمول فتتأخر أول زيارة، وقاعدة
البيانات المجانية يحذفها Render بعد ٣٠ يومًا من إنشائها.

## الاختبارات

```bash
cd backend
../.venv/Scripts/python manage.py test tests
```

148 اختبارًا تقفل القواعد التي لا يجوز كسرها لاحقًا: توازن القيود، رفض القيد غير
المتوازن، منع حذف قيد مرحّل، عكس القيد بدل الحذف، عدم تكرار العملية عند إعادة
الإرسال، فصل بيانات كل مزرعة، تحقق الصلاحيات، نسبة كل عملية لمن نفّذها، وتحقق
تباين الألوان قبل النشر — ومعها قواعد الفرعين: العلف أصل حتى يُصرف، وتكلفة الصرف
تقع على فرع المستودع، والبيع المختلط يُقسَّم دخله بين الفرعين، والتكلفة التأسيسية
لا تدخل الأرباح، ومجموع أعمدة الفروع يساوي إجمالي المزرعة.

## بنية المشروع

```
backend/
  config/            إعدادات Django والمسارات
  apps/
    core/            النماذج الأساسية: UUID، الطوابع، الحذف الناعم، المزرعة، العملات، البذور
    accounts/        المستخدمون، الأدوار، الصلاحيات، العضويات
    audit/           سجل التدقيق (إضافة فقط)
    catalog/         كل القوائم القابلة للتعديل في جدول واحد بشجرة
    customfields/    الحقول الديناميكية وبناء النماذج
    ledger/          الحسابات، القيود، البنود، محرك الترحيل، شجرة الحسابات
    animals/         الحيوانات، النسب، الولادات، الأوزان، الصحة، السجل الزمني
    parties/         الشركاء والعاملون والموردون والعملاء وحساباتهم
    operations/      أوامر العمل: مصروف، إيراد، تحويل، شراء، بيع، نفوق، افتتاحي
    inventory/       مستودعات الأعلاف: أصناف، استلام، صرف، تحويل، جرد، متوسط مرجّح
    production/      الحليب: الكمية اليومية ومبيعات الحليب ومشتقاته
    assets/          التكاليف التأسيسية كأصول ثابتة
    theme/           الهوية البصرية وتحقق التباين
    api/             طبقة REST: تصاريح، مُسلسِلات، عروض، مسارات
  tests/             اختبارات القواعد الحرجة
admin-web/           لوحة الإدارة (Next.js 15، App Router، عربي RTL)
docs/architecture.md المعمارية والقرارات
```

## القواعد المعمارية

1. **لا أحد ينشئ بنود دفتر إلا `apps/ledger/services.py`.** كل أمر مالي يمر
   عبر `post_entry` التي ترفض القيد غير المتوازن قبل لمس القاعدة.
2. **العمليات المركّبة داخل معاملة واحدة.** شراء حيوان يُنشئ الحيوان والقيد
   والتخصيصات معًا، أو لا شيء منها.
3. **لا حذف للتاريخ المالي.** القيد المرحّل يُعكس بقيد مضاد، والسجل الأصلي يبقى.
4. **لا قوائم داخل الكود.** البنود والحالات والسلالات صفوف في `catalog`،
   والعمليات التاريخية ترتبط بالصف لا بالاسم — فتغيير الاسم لا يفسد الماضي.
5. **الأرصدة تُحسب ولا تُخزَّن.** كل رصيد ناتج عن `SUM` على بنود مرحّلة.
6. **كل شيء مرتبط بـ Farm.** المزارع المتعددة مدعومة من اليوم الأول.
7. **الفرع بُعد على سطر القيد لا على القيد.** فاتورة واحدة تنقسم بين تربية
   وتسمين، ومجموع أعمدة الفروع يساوي إجمالي المزرعة دائمًا.
8. **العلف أصل حتى يُؤكل.** الشراء يزيد قيمة المستودع، والصرف وحده يصير مصروفًا
   على فرع ذلك المستودع — بمتوسط التكلفة المرجّح لحظة الصرف.
9. **التأسيسي ليس مصروف شهر.** بناء الحظيرة يُقيَّد أصلًا ثابتًا، فلا يظهر الشهر
   الذي بُنيت فيه خاسرًا.
10. **بند الإيراد يُختار من الحيوان لا من المستخدم.** المولود المباع يذهب إلى
    «مبيعات المواليد»، والمستبعَد إلى «مبيعات الفرزة»، وما سواهما إلى «مبيعات
    الحيوانات» — بلا حقل إضافي يُملأ يدويًا ويُنسى.
